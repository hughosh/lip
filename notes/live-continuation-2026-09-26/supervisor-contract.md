# Supervisor contract recommendation — 2026-09-26

Scope: read-only design review of H-DEP-2 and the launchd, entry-point, and deployment paths. No code, account, job, or process action was taken. The reported 327,862 retries and flat-account closeout are coordinator observations, not reverified here.

## Smallest coherent change

Use `RunAtLoad=true` and a `KeepAlive` dictionary containing **`SuccessfulExit=false`**, with an explicit `ThrottleInterval` (for example, 60 seconds). Thus launchd starts the job at load, restarts an unexpected nonzero exit (including a Go panic, which exits nonzero), and leaves a zero exit stopped. Retain `/usr/bin/caffeinate -is <harness>`, the existing argv/config/rung checks, one-instance lock, durable halt latch, and the harness's SIGINT/SIGTERM-to-drain path. H-DEP-2 must state this conditional policy; its current “restart on any exit, including exit 0” clause and the install report are false under the proposed behavior. A launchd throttle bounds *retry frequency*, not total retries: launchd alone cannot provide a finite retry budget or classify an arbitrary persistent operational failure.

The current `exitDrained=0`, `exitFailed=1`, `exitRefused=2` cannot be fed unchanged to `SuccessfulExit=false`: refusal 2 would still retry forever. Preserve manual CLI compatibility by adding an explicit supervised invocation marker to deployed argv and mapping **only a structural `refusal` in supervised mode to process status 0**. Manual refusals retain status 2 and diagnostics; operational failures retain status 1; a verified flat, unrested planned drain retains status 0. The marker must be known before flag parsing, because `flag.ExitOnError` currently calls `os.Exit(2)` inside `Parse`; change the production parse path to classify parse errors as refusals as well. Put the marker first in generated argv and test malformed later arguments. An unknown or misspelled marker itself cannot be classified by this scheme; pin its generation with the actual parser and a child-process check. A simpler global refusal-to-zero mapping would break manual CLI status compatibility.

Do not make the supervisor decide whether inventory is flat, forward a signal in place of the harness, or call `launchctl` from `-deploy`. The authorized exit remains the existing drain permit, complete fresh account truth, successful store shutdown, and latch; an unplanned drain with exposure still stays alive. The deployed `-live` flag remains subject to the per-write sentinel check. Replacing an installed plist still requires bootout/rebootstrap and an operator's decision to load it; changing the file alone does not change the loaded job.

## Tests and compatibility checks for the implementation

- Replace the old `KeepAlive=true` assertions in `launchd_test.go` and the installed-plist check in `deploy_test.go` with checks for `SuccessfulExit=false`, `RunAtLoad=true`, a positive throttle, and the required empty-element plist booleans. Keep XML escaping and `/usr/bin/caffeinate -is` assertions. Update or retire the anchored `M-L-KEEPALIVE` mutation so it tests loss of **conditional crash recovery**, rather than an obsolete `emitTrue` sequence.
- Exercise the *real entry point* as a child: supervised structural refusal after a previously valid deployment (for example, a now-ineligible ticker) exits zero and is terminal; supervised malformed flags are terminal; supervised operational failure exits nonzero; planned flat drain exits zero; manual structural refusal still exits 2. Assert diagnostics remain visible for terminal refusals. A pure `run()` test misses `main`'s `os.Exit` and parser behavior.
- On macOS with a disposable, account-free child, verify that `/usr/bin/caffeinate -is` propagates zero/nonzero child status as the proposed policy assumes, and that an operator SIGTERM delivered through the loaded job reaches the harness's signal handler and allows it to remain alive until its drain condition. The present tests inject signals directly into Go channels; they do not establish signal delivery through `caffeinate` or launchd. If that check fails, the process ownership arrangement needs a separate narrow repair before installing this policy.
- Check the generated plist with launchd's parser in a disposable job: this repository has already found a plist that passed XML/plutil checks but failed `launchctl bootstrap`. An installed-file assertion alone does not establish actual supervisor behavior. Preserve the existing deployment rule that tests never load the live job.

This change addresses the observed obsolete-job refusal loop. It does not establish CR2 live readiness or solve external alarm acknowledgment and escalation.
