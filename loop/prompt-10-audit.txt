## HOW EACH SECTION OF THE DIRECTIVE WAS IMPLEMENTED

### §1 Package and files

All nine files created with the names you gave. Every production file carries a
`// confidence: high` trailer. The additive constructor is
`risk.NewSeededPortfolio(map[string]num.Qty) *Portfolio`: it copies non-zero
positions into a fresh portfolio, drops flat entries rather than storing zeros,
and touches neither `driftStreak` nor `seenTrade` nor `orders`.

Its rationale, as written in the doc comment: startup cannot use
`ReplacePositions`, because that function compares a poll against a prior belief
and at startup there is no prior belief. A fresh `Portfolio` has an empty `q`, so
every non-zero position the exchange reports reads as a full-magnitude delta —
on any account holding more than `pos_drift_hard`, an immediate SEV1
`POSITION_DRIFT` and a global stop, fired by the act of starting up correctly on
the exact path H-ORD-5 calls normal after a SIGKILL.
`TestSeededPortfolioAdoptsWithoutManufacturingDrift` asserts that contrast
directly: the same input through `ReplacePositions` on a fresh portfolio DOES
set `Stop`.

### §2 Durable latch

`LatchRecord`, `LatchStore`, `FileLatch`, `NewFileLatch` exactly as specified.

- `Load` returns `(rec, false, nil)` for `os.IsNotExist` and NOTHING else.
- Empty, truncated, JSON null, empty object, wrong version, missing trigger,
  non-positive timestamp and unknown fields all return `present=true` plus an
  error. `DisallowUnknownFields` supplies the diagnostic; the verdict is still
  latched.
- `Ensure` is `O_WRONLY|O_CREATE|O_EXCL` at 0600, then Write, `Sync`, `Close`,

  or on the interface.
- `NewFileLatch` requires an ABSOLUTE path. That is an addition to your section
  and is flagged for adjudication: the argument written into the code is that a

### §3 Write-before-transition controller

`StopCause`, `GlobalDecision`, `BootstrapEffects`, `NewGlobalController`,
`Decide`, with the field sets you gave.

- `NewGlobalController` calls `store.Load()` immediately. A load error does not
  fail construction — it bootstraps `Latched=true`, `BlockAdding=true`,
  `RetryLatch=true`, `SEV1 LATCH_INVALID`. The reason written into the code:
  failing construction leaves the process with no controller, which is a process
  that cannot latch the stop it is in the middle of discovering.
- `NewStartup` requires a controller with a private `booted` flag set, which only
  `NewGlobalController` sets. `&GlobalController{}` and `nil` are both refused.
  That is the "may only be constructed from an already-bootstrapped controller"
  requirement.
- `Decide` order: validate cause -> `Ensure` -> set cached `Latched` -> call
  `quote.NextGlobal` -> return.
- On persistence failure: `Committed=false`, `BlockAdding=true`,
  `RetryLatch=true`, `SEV1 LATCH_WRITE_FAILED`. **The in-memory transition is NOT
  taken**; `dec.State` is the input state. This is an interpretation of your
  section and is flagged: your text says "return the current state with
  Committed=false", which the code reads as the state not advancing. The
  argument written in is that a process sitting in WINDING_DOWN believing it
  latched would restart into a directory with no file and resume adding — HR-009
  with the harness having been told the write failed.
- A malformed `StopCause` (empty trigger, non-positive timestamp) is NOT dropped:
  same blocked-adding, retry-requested shape, and nothing reaches the disk.
- A zero `StopCause` means "no stop requested" and passes the input through, which
  is how STARTING -> RUNNING and WINDING_DOWN -> DRAINED are taken.

The SIGTERM test is a subprocess test as directed: the binary re-executes itself,
