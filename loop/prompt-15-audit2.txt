## HOW EACH DIRECTIVE ITEM WAS IMPLEMENTED

### 2. Writer ownership and shutdown

`Run` now claims the FIFO through `claimWriter` and releases it through
`releaseWriter`, both under the store mutex:

- `claimWriter` refuses when a writer is running, has already gone, or the store
  is closed. A concurrent second `Run` returns immediately without touching the
  FIFO.
- `releaseWriter` latches `writerGone`, sets `healthy=false` and `adding=false`,
  clears `inflight`, and wakes observers on the result channel.
- `writerGone` is TERMINAL: a later `Run` is refused rather than resuming. A
  store whose writer returned has a gap in it, and health that recovered would
  assert durability for whatever was submitted during the gap. FLAGGED — the directive
  asks only for the revocation, not for the refusal.
- `inflightSince` is now a `time.Duration` from an injected `monoNow`. Wall
  milliseconds remain for records only (`first_ms`, `bound_ms`, the journal's
  `written_ms`).
- `Close` refuses, WITHOUT changing state, while a write is in flight or the
  FIFO is non-empty, and the test proves the store is still usable afterwards.
- The closed check moved INSIDE `submit`'s critical section, so `submit` now
  returns `(Receipt, error)` and every submission method propagates it.
  `checkOpen` is gone.
- `DispatchPermit.Order` consults `Health().AllowsAdding()`, which is now a
  conjunction over `healthy && fault=="" && !writerGone && !closed`. A reducing
  permit does not consult it at all, so it survives writer loss and close.

### 3. Permanent-failure semantics

Kept the classification and kept popping the head, so later audit rows still
progress. Added `Store.fault`, a sticky string set on any permanent failure:

- `healthy` and `adding` go false at the same moment;
- the terminal `Result` is published as before;
- the transient recovery branch is guarded by `s.fault == ""`, and
  `healthLocked` ANDs on it independently, so no later sequence crossing
  `recoverAt` can heal the store;
- `submit` does NOT refuse on a fault, so later valid audit rows are still
  accepted and written;
- `Health().LastError()` reports the fault, which is what `lip-eyq` and
  `lip-3af` will raise `SEV1 STORE_RECORD_REJECTED` from.

### 4. Database opening

`Open` now runs `distinctArtifacts` first, then `openSQLite`, which runs
`inspectDatabase` BEFORE opening any writable connection:

- `distinctArtifacts` rejects identical cleaned paths, SQLite's own `-wal`,
  `-shm` and `-journal` sidecars, and two names for one file via `os.SameFile`.
- `inspectDatabase` opens `mode=ro&_pragma=query_only(1)`. A missing or
  zero-length file is fresh. Version zero WITH any user table is rejected;
  version one whose table set is not exactly `userTables` is rejected; any other
  version is rejected. Nothing is written on any of those paths -- the test
  asserts the foreign database's table list AND its journal mode are unchanged.
- `writerDSN` carries `_pragma=synchronous(NORMAL)` and
  `_pragma=foreign_keys(ON)`, so a replacement connection from the pool inherits
  them. `journal_mode=WAL` stays an explicit statement because it is a database
  property, not a connection one.
- `createSchema` runs the DDL and `PRAGMA user_version=1` in ONE transaction.
- `assertPragmas` is the retained read-back, now also checking `foreign_keys`.
- `Store.Pragmas` is gone; `Store.pragmas` is private and used by the tests.
- `deferredTables` is now exactly your list: `balance_poll`, `market`,
  `order_event`, `order_intent`, `position_poll`, `snap`, `uptime`.

### 5. The journal, both ways

- `openJournal` records whether it CREATED the file, and on creation syncs the
  file and then its parent directory through the `syncDirFn` seam.
- `reconcile` now reads `anomalyJournalStates` -- every row plus whether the
  database believes its text is durable -- and fails closed on a row whose
  `journaled_ms` is set and whose id has no line in the JSONL.
- Both legitimate null-`journaled_ms` crash windows are repaired exactly as
  before, and truncated, malformed, conflicting and text-only records are still
  rejected.

One addition, FLAGGED: a journal file this call created and could not sync is
REMOVED. Left behind, the next `Open` would find an existing journal, skip the
creation path, and never sync the entry -- so one failed sync would permanently
downgrade the artifact it guards. The test asserts this by counting syncs across
a failed open, a successful open, and a reopen.

### 6. Transports

- `NTFYSender.valid()` and `HTTPSDeadman.valid()`; `Send` and `CheckIn` return
  fixed `errNoSender`/`errNoDeadman` for a zero or nil receiver and never
  dereference one.
- `NewService` tests `!sender.valid()` and `!dead.valid()` rather than `== nil`.
- `transportError` classifies from the error's TYPE and the sentinels --
  `context.Canceled`, `context.DeadlineExceeded`, `url.Error.Timeout()`,
  `*net.OpError` -- and quotes NOTHING from the error text. No `*url.Error` is
  returned or wrapped anywhere.
- `refuseRedirect` returns a package-level `errRedirect` naming neither url;
  `transportError` recognises it and preserves the classification.
- A non-2xx still reports `resp.Status`, which carries no URL.

### 7. The scheduler

`Effects.NextStepMs` is the earliest of: the nominal heartbeat, every failed
alert's next attempt, every rate-limit bucket's reopening, the failed health
notice, the failed heartbeat, the failed dead-man check-in, and -- while
`Health().Pending() > 0` or the store is unhealthy -- `nowMs +
hstore.HealthPollInterval`. `NextHeartbeatMs` is unchanged and remains nominal.

- `Service.dueAt` prefers this process's `retryAt` and falls back to the
  PERSISTED `attempts` and `last_attempt_ms`, so a restart does not treat a row
  already attempted six times as brand new.
- The urgent health notice is owed on the transition AND on a first observation
  that is already unhealthy, and is retried on the 1-60 second ladder until it
  lands.
- A failed heartbeat is retried on the ladder; the nominal hourly cadence does
  NOT move when a retry succeeds.
- A failed dead-man check-in is retried on its own ladder rather than waiting
  for the next heartbeat.
- `hstore.HealthPollInterval` is a new exported constant, one second, so the
  deadline `lip-3af` must honour is named where it is enforced.

### 8. The directive's adjudications of v1's flagged choices

Every "accepted unchanged" item is unchanged. `Health()` still conservatively
mutates while observing a stall and now uses `monoNow`; the one-second deadline
it implies is published as above for `lip-3af` to drive.

### 9. Ratchets

89 preserved, 17 added with the directive's exact IDs and catchers. Evidence
above.

## FLAGGED CHOICES

1. **`writerGone` refuses a later `Run`.** The directive asks for revocation on
   writer loss; refusing a restart is an addition. The argument is that a store with a gap
   cannot honestly recover, and a second `Run` that restored health would assert
   durability for records submitted during the gap. If a restarted writer should be
   allowed to resume, it comes out.

2. **A failed journal creation removes the file it created** (§5 above).

3. **`submit` returns `(Receipt, error)`.** Forced by moving the closed check
   into the append's critical section, but it is a public signature change to
   every submission method.

4. **`Service.dueAt` falls back to persisted state only when this process has no
   memory of the row.** A row this process has already retried uses its own
   `retryAt`.

5. **The health poll is published only while `Pending() > 0` or the store is
   unhealthy.** A store that is idle and healthy has no blocked writer to
   observe, so a permanent one-second wakeup would be noise. If it should be unconditional, say so.

6. **`transportError` maps `*net.OpError` to `"could not <op>"`** -- the OP
   only, never the address. That is the one place a category is taken from the
   error rather than from a sentinel.

7. **`hstore.HealthPollInterval` is exported.** `ping` needs it and `lip-3af`
   will, and duplicating the constant in two packages is how they drift.
