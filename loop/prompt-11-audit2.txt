## HOW EACH DIRECTIVE ITEM WAS IMPLEMENTED

### 1. GlobalController as a real choke point

The guard is stated over the OUTPUT rather than over the arguments, because the
break was a caller supplying `GlobalInput.Stop` and no cause.
`GlobalController.Decide` now refuses to return a publishable transition into
WINDING_DOWN unless the durable state on disk already justifies it:

    if in.Stop && !c.latched {   // zero StopCause
        -> current state, Committed=false, BlockAdding=true, RetryLatch=true,
           SEV1 STOP_CAUSE_MISSING, nothing written

Once the latch IS on disk, a causeless `Stop` is permitted -- the durable state
justifies it. `TestCauselessStopCannotEnterWindingDown` first asserts that the
control input genuinely produces WINDING_DOWN in `quote.NextGlobal`, so it cannot
pass vacuously.

### 2. Startup integrated with the controller

`Startup.Run(ctx, quote.GlobalInput, now) Attempt`. `Attempt.State` is gone;
`Attempt.Decision` is a `GlobalDecision` produced by the controller.

- No cause: `commit` calls `ctrl.Decide` with `TruthReadable=true,
  Reconciled=true`, so STARTING -> RUNNING is taken by §5.1.
- Every cause is committed BEFORE the licence is returned. If any commit fails,
  no Adoption is returned at all and the attempt retries.
- UNKNOWN_RISK is reached through the state machine: `fail()` sets
  `in.TruthReadable = consecutiveFailures < 3`, and §5.1's STARTING rule turns
  that into UNKNOWN_RISK/GTTruthFailed. Nothing assigns a state.
- A latched process cannot regress: every outcome goes through `Decide`, so A14
  produces WINDING_DOWN/GTLatch on failing AND succeeding attempts.
  `TestLatchedStartupFailureCannotRegressToStartingOrUnknownRisk` covers both.

### 3. Adoption sealed

`Adoption` is now an exported INTERFACE with the eleven accessors plus an
unexported `isAdoption()`; `adoption` is the private concrete type;
`Attempt.Adoption` is the interface and its zero value is nil. `Summary()`
deep-copies the position map and all three slices via `StartupSummary.clone()`.

The seal test asserts the KIND is an interface, that at least one method is
unexported, that the exported surface matches an eleven-name allowlist, and that
`var lifecycle.Adoption` and `lifecycle.Attempt{}.Adoption` are both nil.

### 4. Planned-exit authority bound to a durable stop

`DrainPermit` has three private fields and an invalid zero value.
`NewSignalController(*GlobalController)`; `Handle` sets `in.Stop = true`, calls
`Decide`, and issues the permit ONLY on `Committed`. `Begin(bool, ...)` is
replaced by `BeginPlanned(DrainPermit, mono) error` -- which rejects an invalid
permit -- and `BeginUnplanned(mono)`, which escalates and can never authorise an
exit.

One behaviour is an interpretation and is flagged: `BeginPlanned` on an ALREADY
STARTED unplanned drain upgrades it to planned without restarting the escalation
clock (`TestSignalDuringAnUnplannedDrainCanStillAuthoriseTheExit`). The argument
written in is that an operator who signals a harness already winding down from a
taker fill has asked for the process to end once it is safe to, and that refusing
would make the signal inert exactly when it is most deliberate. If you consider
that out of scope, it comes out.

### 5. Startup consistency

- `ForeignGuard.Classify` runs on the RAW `rest.Fill` slice before anything is
  converted; `convertStartupFills` then runs only over `fe.OwnedFills`.
- A foreign fill with a missing or malformed fee therefore still produces
  `SEV1 FOREIGN_FILL`, is excluded from owned history, and latches
  `foreign_fill`. An unreadable fee on a fill that IS ours remains a hard startup
  failure. Both halves are asserted in
  `TestForeignFillWithUnusableFeeStillLatches`.
- `Startup.walk` loops: a pass that cancelled anything discards its result,
  raises `SEV2 STARTUP_REWALK`, and reruns all four reads WITHOUT incrementing
  the failure counter.
- The final no-cancel pass installs every kept order via
  `portfolio.ReplaceOrders(keptAsLive(kept), nil, true)`. `foreign` is passed nil
  on purpose: no foreign or cancelled order enters our model, and `ForeignGuard`
  has already raised their anomaly, so passing them would double-report.
- `managedSet` takes the KEPT orders rather than every owned resting order.

**The rewalk bound is an addition and is flagged.** `maxSweepRewalks = 3`.
Termination does not depend on it: `Clean` means a complete verifying read found
none of the requested orders resting, and an order the exchange confirmed absent
cannot come back, so an honest source cancels nothing on the rewalk. The bound
exists because an unbounded loop in a startup path is a hang rather than an
error. It is also what turned the `M-L-SWEEP` regression above into a survived
mutation rather than a hang, which is the strongest argument for it and also the
reason it deserves your adjudication rather than mine.
