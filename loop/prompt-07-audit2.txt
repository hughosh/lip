## IMPLEMENTATION CHOICES INSIDE YOUR DIRECTIVE, STATED FOR ADJUDICATION

1. **`M-W-READTOKEN` is implemented as ADDING an exported `Token` field
   alongside the private one**, rather than renaming the private field. A full
   rename would require patching the test files as well, and a mutation that
   edits tests is a mutation that tests whether tests can be broken. The
   exported-field form is production-only, compiles, and is what
   `TestPortfolioTruthHasNoPublicBypass` refuses. Say if you want the rename
   instead.

2. **`M-W-TRUTHFORGE` adds an exported `NoteTruth` that forwards to
   `noteTruth`**, for the same reason: production-only and compiling.

3. **`FrameEffects.Deliver` was RENAMED to `Delivered`**, not kept alongside.
   Keeping a field that says "you may deliver this" next to a method that
   already delivered it is the ambiguity that produced the break.

4. **`ApplyFrame` returns `Resnapshot: true` for a nil handler as well as for a
   core rejection.** You specified the resnapshot for the rejection; the nil
   handler is the same evidential state (core has not seen the frame) and is
   treated the same way.

5. **The quiet clock is not refreshed by a REJECTED frame**, which is what makes
   the F5 assertion in the new test meaningful. You specified this; it is
   restated because it is the mechanism by which a market whose every frame core
   refuses eventually reduces without a second detector.

6. **`newRead` / `newStaggeredRead` test constructors** were added to
   `stub_test.go`, in-package, because `PortfolioRead` is now opaque and no test
   outside the package can build one. The external seal test does not build one.
